# 1. 背景 & 目标

### 1.1 背景说明

当前运营后台已具备“文章添加/消息添加”能力，运营人员可通过“文章信息 + 文章内容”两步流程创建文章，并在文章类型中选择不同内容类型。

本次需求不新建独立的更新通知后台模块，而是在现有文章体系内新增文章类型“更新通知”。运营人员通过现有文章添加功能维护更新通知内容，移动端新增二级页面展示更新通知列表和更新通知详情。

当前文章数据没有独立版本号字段。为降低改造成本，本需求复用现有“摘要”字段，并在文章类型为“更新通知”时将该字段改为“版本号”，在移动端列表页和详情页展示为版本号。

### 1.2 目标说明

- 后台文章类型新增“更新通知”枚举，支持运营通过现有文章添加流程发布更新通知。
- 移动端从“我的”页面进入“更新通知”二级页面，展示文章类型为“更新通知”的已发布文章。
- 移动端列表页按发布时间或创建时间倒序展示，第一条即最新版本。
- 移动端详情页展示更新通知标题、版本号、发布日期和富文本内容。
- 尽量复用现有字段、接口、发布状态和富文本能力，减少新增数据结构。

### 3.2 后台文章添加

### 功能描述

在现有文章添加页面的“文章类型”下拉选项中新增“更新通知”。

运营人员选择“更新通知”后，仍使用现有两步流程创建内容：

1. 在“文章信息”中填写标题、副标题、文章类型、版本号、发布对象、城市、封面等现有字段。
2. 在“文章内容”中通过富文本编辑器维护更新通知详情内容。
3. 提交后按现有文章发布逻辑保存。

### 字段复用逻辑

- 标题：作为移动端列表标题和详情标题。
- 副标题：作为移动端列表卡片下方说明文案。
- 版本号：由原“摘要”字段改名而来，作为移动端展示的版本号，例如 `V3.8.0`。
- 文章内容：作为移动端详情页富文本正文，支持图片 + 文字。
- 是否发布：控制移动端是否展示。
- 文章类型：值为“更新通知”时进入移动端更新通知展示范围。

### 交互逻辑

- 文章类型下拉选项新增“更新通知”。
- 当文章类型选择“更新通知”时，将“摘要”字段文案调整为“版本号”，输入提示调整为“请输入版本号，如 V3.8.0”，且该字段必填。
- 现有图文封面、banner 图字段按当前后台规则保留；移动端更新通知列表和详情不依赖封面字段展示。
- 更新通知详情页展示的图片来自富文本内容，不读取图文封面或 banner 图。

### 3.3 移动端更新通知列表页

### 功能描述

移动端新增“更新通知”二级页面，用于展示已发布的更新通知文章列表。

### 页面结构

- 顶部导航：返回按钮 + 居中标题“更新通知”。
- 顶部说明区：
    - 标题：产品更新通知
    - 副标题：查看版本能力变化、问题修复与体验优化记录
- 列表卡片：
    - 更新标题
    - 版本号
    - 更新日期
    - 发布状态文案
    - 副标题

### 展示规则

- 仅展示文章类型为“更新通知”的文章。
- 仅展示已发布文章。
- 列表按发布时间倒序；若无发布时间，则按创建时间倒序。
- 第一条即最新版本。

### 3.4 移动端更新通知详情页

### 功能描述

用户点击列表卡片后进入更新通知详情页，展示该条更新通知完整内容。

### 页面结构

- 顶部导航：返回按钮 + 居中标题“更新详情”。
- 详情头部：
    - 版本号
    - 发布状态

- 本次更新：

### 展示规则

- 富文本图片和文字按后台上传内容展示。

## 4. 业务流程

### 4.1 主流程

1. 运营人员进入后台“营销中心 / 文章添加”。
2. 在文章信息页选择文章类型为“更新通知”。
3. 填写标题和副标题。
4. 在版本号字段填写版本号，例如 `V3.8.0`。
5. 按现有规则填写发布对象、城市、封面等字段。
6. 点击下一步进入文章内容页。
7. 在富文本编辑器中编辑更新通知详情内容。
8. 点击提交。
9. 系统保存文章数据。
10. 当文章为已发布状态时，移动端更新通知列表展示该文章。
11. 用户从“我的”页面进入更新通知列表。
12. 用户点击列表卡片进入详情页，查看富文本内容。

### 4.2 分支流程

### 未发布文章

- 当“是否发布”为“否”或文章状态为未发布时，不在移动端更新通知列表展示。

### 版本号为空

- 当文章类型为“更新通知”且版本号为空时，后台提交需阻断。
- 提示文案：请输入版本号。

### 富文本内容为空

- 当文章类型为“更新通知”且文章内容为空时，后台提交需阻断。
- 提示文案：请输入文章内容。

### 城市限制

- 如后台文章已有城市字段和城市展示规则，则更新通知沿用现有城市规则。
- 如城市为空或选择全部城市，则面向全部城市展示。

## 5. 状态流转说明

### 5.1 状态定义

|状态|来源|移动端展示|
|---|---|---|
|未发布|文章是否发布=否，或文章状态为未发布|不展示|
|已发布|文章是否发布=是，且文章状态有效|展示|
|已删除|文章被删除或下架|不展示|

### 5.2 状态流转

|流转|触发方式|结果|
|---|---|---|
|未发布 → 已发布|后台提交并设置发布|移动端可展示|
|已发布 → 未发布|后台取消发布或下架|移动端不展示|
|已发布 → 已删除|后台删除文章|移动端不展示|

### 5.3 流转规则

- 移动端只读取已发布且未删除的数据。
- 已发布内容被编辑后，移动端展示编辑后的最新内容。
- 删除或取消发布后，移动端列表和详情均不可继续访问该内容。

## 6. 规则说明

### 6.1 取值规则

|移动端展示项|说明|
|---|---|
|列表标题|展示文章标题|
|列表版本号|展示版本号，即后台更新通知类型下由“摘要”改名后的必填内容|
|列表更新日期|展示到日，格式为 `YYYY-MM-DD`|
|列表副标题|展示后台填写的副标题内容|
|详情版本号|展示版本号，即后台更新通知类型下由“摘要”改名后的必填内容|
|详情标题|展示文章标题|
|详情更新日期|展示到日，格式为 `YYYY-MM-DD`|
|详情正文|展示后台文章内容中的富文本内容|

### 6.2 强制规则

- 文章类型必须新增“更新通知”。
- 当文章类型=更新通知时，原“摘要”字段必须改为“版本号”，且版本号必填，封面图取消必填，对象只有二房东。
- 移动端更新通知只展示文章类型=更新通知的数据。
- 移动端更新通知只展示已发布数据。
- 移动端更新通知详情正文必须以富文本形式展示，不拆成固定结构。

### 6.3 显示规则

- 版本号直接展示后台版本号内容，不额外拼接固定前缀。
- 如版本号填写 `V3.8.0`，移动端展示 `V3.8.0`。
- 如版本号填写 `3.8.0`，移动端展示 `3.8.0`，系统不自动补齐 `V`。
- 日期展示到日，不展示具体时分秒。
- 富文本内容中的图片按移动端宽度自适应展示。
- 富文本内容超出一屏时，详情页支持纵向滚动。
- 文章内容不做Tab切换，直接挪到第一个tab来。

> **Web 端文章列表 UI 参考：**
>
> ![[05_UI图/Web端/文章列表.png]]

### 6.4 排序规则

- 列表按发布时间倒序。
- 发布时间为空时按创建时间倒序。
- 时间相同时按文章 id 倒序。

### 6.5 兼容规则

- 历史文章类型不受影响。
- 现有消息/公告、普通文章的移动端展示逻辑不变。
- 现有文章后台字段不删除、不重命名数据库字段。
- 本需求不新增独立版本号字段，版本号由原“摘要”字段承载并在更新通知类型下改名展示。

## 7. 异常处理机制

### 7.1 后台校验异常

|场景|处理方式|提示文案|
|---|---|---|
|未选择文章类型|阻断提交|请选择文章类型|
|更新通知标题为空|阻断提交|请输入标题|
|更新通知副标题为空|阻断提交|请输入副标题|
|更新通知版本号为空|阻断提交|请输入版本号|
|更新通知内容为空|阻断提交|请输入文章内容|
|富文本图片上传失败|阻断或提示重试|图片上传失败，请重试|

### 7.2 移动端展示异常

|场景|处理方式|
|---|---|
|更新通知列表为空|展示空状态|
|详情数据不存在|展示缺省页或返回列表|
|文章已取消发布|详情页不可访问，提示内容不存在或已下架|
|富文本图片加载失败|展示图片占位或加载失败状态|

## 8. 权限控制说明

### 8.1 后台权限

- 具备文章新增权限的后台用户可创建更新通知。
- 具备文章编辑权限的后台用户可编辑更新通知。
- 具备文章发布权限的后台用户可发布或取消发布更新通知。
- 具备文章删除权限的后台用户可删除更新通知。

### 8.2 移动端权限

- 移动端用户可查看符合发布、城市、发布对象规则的更新通知。
- 如现有文章系统存在用户角色、城市、发布对象限制，更新通知沿用现有限制。
